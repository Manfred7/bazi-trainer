# Тесты: архитектура и как ими пользоваться

Цель — проверять приложение одной командой, без ручного прогона экранов в браузере. Два слоя:

| Слой | Чем | Что проверяет | Команда | Время |
|---|---|---|---|---|
| Логика | Vitest + **fast-check** | правила пути, прогресса, «Узнавания», прогона знака, данные черт | `npm test` | ~2 с, 64 теста |
| Экраны | **Playwright** (`@playwright/test`) | сценарии пользователя в собранном приложении: письмо мышью по чертам, переходы, прогресс, тема, офлайн | `npm run e2e:mac` (на Mac mini) или `npm run e2e` (локально) | 17 с на Mac mini, 12 сценариев |

## 1. Логика: тесты на свойствах (`src/logic/properties.test.ts`)

Вместо пары примеров — правило, проверяемое на сотнях случайных сценариев. Упавший случай fast-check ужимает до минимального и печатает seed.

- **Прогресс (Лейтнер):** уровень всегда 0…5; верно — +1 до потолка, ошибка — 0.
- **Путь знака:** при любой истории шагов верный шаг не опускает знак и поднимает не больше чем на ступень; ошибка без понижения оставляет на месте, с понижением — ровно на одну вниз (не ниже обводки); сессия собирается только из знаков набора, новых не больше `NEW_PER_SESSION`, вопрос о порядке — знакам от `ORDER_MIN_STROKES` черт.
- **«Узнавание»:** правильный вариант есть ровно один, варианты не повторяются, их четыре, направление подходит к знаку. `Math.random` подменён генератором с зерном — случайность приложения тоже воспроизводима.
- **Данные черт:** число черт как в прописях; каждая черта — исходная черта hanzi-writer-data или склейка исходных без разрыва (стык < 60), каждая исходная использована ровно раз; правки 丑 / 辰 / 戌 / 癸 на месте.
- **Прогон одного знака:** модельный тест — случайные последовательности «итог / дальше / повтор» сверяются с простой моделью правила «шаг засчитан ⇔ ошибок ≤ 1».

Чтобы правило было проверяемым без браузера, оно вынесено из экрана в чистую функцию (`src/logic/drill.ts`, `drillReducer`).

## 2. Экраны: Playwright

### Что под тестом

Собранное приложение из корня сайта (как на tiangan.ru): `vite build` → `vite preview` на 127.0.0.1:4176 (`playwright.config.ts`, `webServer`). Устройство — Pixel 7, `ru-RU`, Europe/Moscow, светлая тема, `reducedMotion`. Service worker по умолчанию выключен (`serviceWorkers: 'block'`), офлайн проверяется отдельным тестом с тегом `@offline`.

### Структура

```
e2e/
  fixtures/
    app.ts        приложение под тестом: засев localStorage (storageState), тестовый мост и Math.random
                  с зерном (addInitScript), отрезанные внешние шрифты, автофикстура ошибок страницы
    screens.ts    экранные объекты как фикстуры: start, drill, path, board
    index.ts      mergeTests(app, screens) + expect с матчерами — единый вход для тестов
  screens/        экранные объекты: локаторы и действия, без проверок по смыслу теста
    start.ts      стартовый экран: свободная практика, путь, тема, окно «Новое звание»
    steps.ts      экраны с шагами (прогон знака, путь): next/retry/exit, вопрос о порядке, «Взгляни»
    board.ts      клетки: провести черту, написать знак, нажать черту в вопросе о порядке
  support/
    seed.ts       то, что выполняется в странице до её скриптов
    matchers.ts   toBeAtStep, toHaveResult
    data.ts       ключи localStorage, фабрика прогресса, чтение прогресса
  drill.e2e.ts    «Один знак — все шаги»
  path.e2e.ts     «Продолжить путь»
  practice.e2e.ts «Узнавание», «По памяти»
  app.e2e.ts      обход экранов, тема, засев, офлайн (@offline)
```

### Как тест «пишет» знак

Тестовый мост `src/logic/e2e.ts` включается только если тест до загрузки страницы поставил `window.__BAZI_E2E__ = true`; в обычной работе приложения он ничего не делает. Клетки письма и вопроса о порядке регистрируются в мосте, и `window.__bazi.strokes(kind)` отдаёт средние линии черт в пикселях окна. По ним тест ведёт **настоящую мышь** (`page.mouse`) — проверяется и сама обработка ввода Hanzi Writer, на собранной версии.

### Контракт разметки (`data-*`)

| Где | Атрибут | Значения |
|---|---|---|
| каждый экран `<main>` | `data-screen` | start, drill, drill-pick, drill-result, path, path-result, quiz, recall, trace, study, result, chain, charts, cycle, history, stats |
| прогон знака `<main>` | `data-char`, `data-step`, `data-try`, `data-result` | stem-geng; intro · order · trace · half · glance · recall; 1, 2…; pending · ok · fail |
| путь `<main>` | `data-char`, `data-stage` | ступень или `order` |
| статус шага | `data-testid=step-status`, `data-state`, `data-written`, `data-mistakes` | writing · peek · ok · fail (письмо); asking · done (вопрос о порядке) |
| итоги прогона | `li[data-step]`, `data-tries` | ошибки попыток: `2,0` |
| «Узнавание» `<main>` | `data-answer`, `data-revealed`, `data-done`, `data-direction`; варианты — `data-option` | |
| клетки | `data-testid=board` (`data-hanzi`), `data-testid=order-board` (`data-written`) | |
| кнопки | `data-testid` | next, retry-step, hint, restart, again, animate, exit, menu, drill-again, drill-other, path-start, path-again, free-start, charts, cycle, stats, history |
| выбор | `data-char`, `data-mode`, `data-deck`, `data-length`, `data-quiz-length`, `data-theme-option` | |

Тексты и вёрстку можно менять свободно: тесты опираются на этот контракт и на роли с доступными именами (кнопка «В меню»), а не на CSS-классы и надписи.

### Правила

1. **Проверки только web-first** (`toHaveAttribute`, `toBeVisible`, `expect.poll`) — они сами ждут. `waitForTimeout` запрещён линтером (`eslint-plugin-playwright`), промисы без `await` — тоже.
2. **Экранный объект = локаторы + действия**, проверки — в тесте; ветвления («если шаг „Взгляни“ — дождаться конца показа») живут в экранных объектах, сценарии линейные и разбиты на `test.step`.
3. **Ошибки страницы — провал теста:** `pageerror`, упавшие запросы и ответы ≥ 400 (на уровне контекста — видны и запросы service worker); `console.error` — во вложение отчёта.
4. **Детерминизм:** `Math.random` с зерном (`test.use({ seed })`), фиксированные устройство, язык, часовой пояс, тема.
5. **Состояние до теста — через `storageState`** (`test.use({ storage: { progress: progressOf({...}) } })`): применяется при создании контекста, перезагрузки его не затирают. Каждый тест строит своё состояние сам.
6. **Отрицательный контроль:** у ключевых сценариев есть парный — без ключевого действия (не рисуем) или с ошибками — он обязан дать «не засчитано».
7. **Внезапные окна** (например, «Новое звание» после засева) закрываются через `page.addLocatorHandler` в экранном объекте, а там, где окно — часть проверки, его появление проверяется явно.

## 3. Где запускать

**Mac mini (основной способ):** `npm run e2e:mac [-- аргументы playwright]`, например `npm run e2e:mac -- e2e/drill.e2e.ts -g "庚"`. Скрипт `scripts/e2e-mac.ps1`:
1. делает снимок рабочего дерева вместе с незакоммиченными правками — отдельным коммитом через временный индекс (ваш индекс и ветка не меняются);
2. отправляет его на мак (`git push macmini:work/bazi-trainer`, ref `refs/e2e/snapshot`);
3. на маке: checkout снимка, `npm ci --ignore-scripts` при смене `package-lock.json`, `npx playwright test`;
4. забирает отчёт в `playwright-report-mac/` (и `test-results-mac/` при провале), код выхода — как у прогона.

Отчёт: `npx playwright show-report playwright-report-mac`. Трасса упавшего теста — `npx playwright trace open <trace.zip>`, затем `trace actions` (видно, на каком действии застряло).

**Локально:** `npm run e2e`. На ноутбуке параллельные браузеры мешают друг другу: один тест — 2,5 с, но весь набор в 4 потока ~1 мин. В кэше Playwright на ноутбуке нет облегчённой headless-оболочки (скачивание блокируется), поэтому в конфиге `channel: 'chromium'` — полный Chromium.

## 4. Проверено

- Весь набор: 12/12 на Mac mini за 17 с; логика — 64/64 за 2 с.
- **Мутационная проверка:** правило прогона нарочно испорчено («засчитано при двух ошибках») — упали 2 теста на свойствах и 2 сценария экранов (庚 и отрицательный контроль). Тесты ловят такие поломки.
- Офлайн: после первой загрузки service worker управляет страницей; без сети приложение открывается и запускает прогон знака.

## 5. Грабли, которые уже собраны

- `page.mouse.move(..., { steps: 6 })` — каждый подшаг ждёт кадра; 6 подшагов на точку делали письмо знака в 5 раз медленнее. Средние линии подробные, хватает `steps: 2`.
- Средние линии Hanzi Writer разреженные (у длинной вертикали 2 точки) — «нет разрывов» проверяется по стыкам склеенных черт, а не по расстоянию между точками.
- На маке `npm ci` падал на `sharp` (качает libvips с GitHub, таймаут): sharp нужен только генератору иконок — `--ignore-scripts`.
- Строки, отправляемые из PowerShell в `ssh … bash -s`, получают CR: последняя строка скрипта должна заканчиваться переводом строки, иначе `exit 1\r`.
- Засеянный прогресс может поднять звание — появляется окно «Новое звание» и перекрывает клики.
